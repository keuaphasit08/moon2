# Moonvera Plus+

Landing Page ภาษาไทย React + Vite + Tailwind CSS + Lucide React หน้าที่รันจริงและข้อมูลสินค้าอยู่ใน `src/App.jsx` (entry: `src/main.jsx`) ไม่มี Custom CSS แยกไฟล์

```sh
npm install
npm run dev
```

สร้าง production bundle ด้วย `npm run build` (ผลลัพธ์ `dist/`)

## รูปภาพ

ดูตารางครบ 37 ไฟล์ใน [IMAGE-AUDIT.md](IMAGE-AUDIT.md) ตรวจภาพจริงทุกไฟล์ก่อนทำเว็บไซต์ ทั้งหมดเป็นกระเป๋า จึงปรับหมวดให้ตรงกับภาพ ไม่ใช้ Unsplash และไม่สร้างสินค้าเสื้อ/หมวก/แก้ว/ร่มที่ไม่มีภาพ

- `images/` เป็นต้นฉบับ ไม่แก้ไขหรือลบ
- `public/images/product-1.jpg` ถึง `product-37.jpg` เป็นสำเนาย่อด้านยาวไม่เกิน 900px คุณภาพ JPG 80% จากต้นฉบับหมายเลขเดียวกัน ใช้ object-contain และกรอบกำหนดสัดส่วน
- ภาพทั้ง 37 ใบแสดงทันทีในแท็บ “ทั้งหมด” และกรองตามหมวดได้
- ไม่มีไฟล์ที่ไม่ได้ใช้ Hero ใช้หมายเลข 1,25,18,4 และ Portfolio ใช้ 3,9,17,24,34,36
- สำเนารวมประมาณ 5.9 MB เทียบต้นฉบับ 9.8 MB ภาพนอก Hero lazy-load

## สถานะการตรวจสอบ

ผ่าน `npm run build` และ React server rendering ตรวจ section anchors, alt ของภาพที่ render และเส้นทางภาพ/ต้นฉบับครบ 37 คู่

ได้เขียน responsive breakpoints สำหรับ 375, 768, 1280px แต่ **ยังไม่ได้ทดสอบด้วยเบราว์เซอร์**: สภาพแวดล้อมปฏิเสธเปิดพอร์ต dev server ด้วย EPERM และ Chrome headless ไม่สามารถเริ่มทำงานได้ จึงยังไม่ยืนยันเรื่อง horizontal scroll หรือผลของการคลิกจริง

รายการตรวจต่อบนเครื่องที่เปิดเบราว์เซอร์ได้:

1. ที่ 375/768/1280px: ตรวจ `document.documentElement.scrollWidth <= window.innerWidth`, ความครบของสินค้าในภาพ, เมนูมือถือ และ CTA ไม่บัง footer
2. สลับทุกหมวดและกลับแท็บทั้งหมด ตรวจ Network ว่าภาพทั้ง 37 โหลดได้
3. กดขอราคาสินค้าแต่ละหมวด: ต้องเลื่อนไป quote และเลือกชื่อเดียวกันใน dropdown
4. ส่งฟอร์มว่าง/เบอร์ 8 หลัก/ตัวอักษร/ไม่ติ๊ก PDPA: ต้องเห็น error ใต้ช่อง; เบอร์ตัวเลข 9–10 หลักผ่าน
5. แนบ JPG/PNG/PDF ต้องแสดงชื่อไฟล์; ไฟล์อื่นหรือเกิน 10 MB ต้อง error
6. กรอกข้อมูลทดสอบถูกต้อง: ต้องเห็นข้อความ “ขอบคุณที่ทดลองกรอกข้อมูล” และแจ้งว่ายังไม่ส่งข้อมูลจริง
7. ทดสอบ FAQ, keyboard navigation, focus, modal และ active navbar ตาม scroll

## ก่อนเปิดใช้งานจริง

- กำหนด `CONTACT.phone`, `line`, `facebook`, `response` และ endpoint ที่ยืนยันแล้ว ปัจจุบันปุ่มติดต่อแจ้งว่ารอข้อมูล ไม่ลิงก์ไปบัญชีสมมติ
- ฟอร์มเป็นการจำลองด้วย setTimeout เท่านั้น ไม่มี fetch ไม่มีการบันทึกข้อมูล handleSubmit รวบรวม FormData พร้อมคอมเมนต์จุดเชื่อมต่อ backend
- เมื่อเชื่อม endpoint ต้องจัดการ HTTP error, server validation, ไฟล์แนบ, spam และแสดงความสำเร็จจริงเฉพาะเมื่อเซิร์ฟเวอร์ยืนยัน
- เปลี่ยน STATS, CLIENTS, REVIEWS เป็นข้อมูลจริงที่ได้รับอนุญาต หรือนำตัวอย่างออกก่อนเผยแพร่
- ยืนยันข้อความมาตรฐานสินค้า เงื่อนไขการผลิต ขั้นตอน Mockup ขั้นต่ำ ราคา ระยะเวลาผลิต และเวลาตอบกลับ
- ใส่นโยบาย PDPA / เงื่อนไขฉบับจริง ข้อมูลผู้ควบคุมข้อมูลและสิทธิผู้ใช้ พร้อม QR ของบัญชีจริง
- ทำ browser QA ตามรายการด้านบน โดยเฉพาะ horizontal scroll และฟอร์มบนมือถือ

Google Fonts ใช้ Noto Sans Thai 400/500/600/700 ต้องเชื่อมอินเทอร์เน็ตเพื่อดาวน์โหลดฟอนต์ครั้งแรก
